# The sources whose code can change what a saved pipeline recipe or prepared shader means
# (cmake/PipelineRuntimeIdentity.cmake hashes them into WWHD_PIPELINE_RUNTIME_ID). A change to any of
# them makes earlier recipes, head starts and model sweeps unusable; a change anywhere else keeps them.
#
# Why these: a Vulkan recipe is (vertex shader identity, pixel shader identity, fixed state, descriptor
# layouts, SPIR-V). A shader's identity is the hash of its generated GLSL text and resource mapping
# (gfx/vulkan/shaders.cpp portable_output_identity), so code that only changes which shaders or states
# the game asks for makes new identities and never matches an old recipe. What has to be covered is code
# that turns the same identity or state into a different pipeline: the renderers (gfx), the GX2 state and
# shader keys (gx2), the shader decompiler (third_party/cemu), the guest ABI headers, and everything that
# rewrites, replaces or adds shaders and pipelines outside gfx (graphics packs and shader overrides, the
# HUD, clouds, background shaders, recipe groups). tools/release/test_pipeline_identity_inputs.py fails
# when a translation unit listed here includes a runtime header that is not, or when a source outside
# the list creates pipelines or shaders.
#
